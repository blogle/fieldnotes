# CI and source releases

Fieldnotes consumes the `blogle/sdlc/v2` compatibility channel. `flake.lock` pins the exact revision; generated GitHub workflow callers use that same full SHA. Fieldnotes owns test derivations and artifact publication. SDLC owns evaluation, Hestia scheduling/cache use, policy checks, and release coordination.

## Consumer contract

`ci.nix` exports exactly `check`, `verify`, and `publish` through `sdlc.lib.mkConsumer`.

| Stage | Named outputs | Purpose |
| --- | --- | --- |
| `check` | `syntax`, `contracts` | JavaScript/Python syntax, workflow lint, site config, generated adapters, changelog fragments |
| `verify` | `integration`, `browser`, `publisher`, `package` | HTTP/reload/Git behavior, browser interactions/offline exports, release-hook invariants, packaged external consumer |
| `publish` | Executable Nix app | Upload and verify the exact merged source archive; emit identity-bound receipts |

Each named check is independently buildable, for example `nix build --no-link .#ci.x86_64-linux.verify.browser`. `just ci-check` and `just ci-verify` select all the appropriate named derivations. CI currently runs on x86_64 Linux; package outputs also exist for other supported systems but are not claimed as hosted CI coverage.

```sh
nix develop -c just ci-check
nix develop -c just ci-verify
nix run .#sdlc -- install --check
```

The Nix tests copy source to a writable sandbox, link a fixed-output npm dependency environment, and run without network downloads. Chromium comes from Nix, not npm. Browser downloads and disposable Git histories stay in temporary directories. Production packaging omits browser-test dependencies and does not install anything into a consumer project's directory.

## Generated workflow adapters

The `.github/workflows/sdlc*.yml` callers, `.mergify.yml`, and `renovate.json` are generated by the pinned SDLC CLI. Do not independently edit their workflow revisions or copy shared workflow internals into this repository.

Use `nix run .#sdlc -- update` to advance the compatible channel and regenerate adapters together. `sdlc install --check` verifies the lock/adapters agree; it does not prove that GitHub Apps and live rulesets have been installed.

## Release fragments

An externally meaningful change adds `.changes/<topic>.json` with `type`, `semver`, and `summary`. Source releases start at the version selected by SDLC from the available tags and fragment intent. Do not manually generate `.sdlc/release.json` or publish from a feature branch.

```json
{
  "type": "feature",
  "semver": "minor",
  "summary": "Add independent download, annotation, and in-page diff tools"
}
```

SDLC assembles a rolling release PR, verifies the deterministic manifest and generated changelog, merges the authorized candidate, and invokes Fieldnotes' publish hook from the exact resulting commit.

## Source archive publication

`scripts/publish.py` receives `SDLC_RELEASE_VERSION`, `SDLC_RELEASE_MERGED_SHA`, `SDLC_RELEASE_SOURCE_SHA`, and `SDLC_RELEASE_RECEIPTS`. It checks the checkout/parent/manifest identity before calling GitHub.

1. Use `git archive` on the exact merged commit, never working-directory files.
2. Compress with fixed gzip metadata and name the asset `fieldnotes-<version>-<merged-sha>.tar.gz`.
3. Inspect the release's existing assets. Upload only if the exact name is absent; never overwrite it.
4. Download the remote asset and verify its SHA-256 against the locally produced bytes.
5. Atomically write the schema-1 receipt with the name, digest, version, merged SHA, and source-main SHA.

The shared publisher creates/finalizes the GitHub Release and validates receipts. The consumer hook does not create tags, bypass protection, or activate releases. A retry reuses existing matching bytes; a digest conflict fails. Unit tests cover identity rejection, remote read-back, idempotence, and refusal to overwrite a conflict. Tests mock GitHub; they do not claim that an actual hosted release has occurred.

## Repository activation

The source repository is public at [blogle/fieldnotes](https://github.com/blogle/fieldnotes). Publishing its initial branch enables GitHub to see the workflows; it does not by itself complete SDLC fleet onboarding.

An authorized administrator must install/enable Mergify, provision the release GitHub App and its scoped secrets, verify/apply the canonical rulesets, create the required ruleset attestation, and explicitly activate releases. Follow the [pinned SDLC protocol](https://github.com/blogle/sdlc). Keep `SDLC_RELEASE_ACTIVATE` false until those prerequisites are satisfied. Private App keys must not be committed or passed to coding agents.

Nix consumers can pin the repository's current revision now and adopt version tags after successful releases. `flake.lock` records their exact chosen source independently of cache availability.
