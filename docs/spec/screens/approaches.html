Documentation distribution approaches

Architecture comparison example. Select an approach, record project-specific constraints, and copy a decision for an agent to implement. Use Review to annotate a trade-off directly.

Per-project implementation

Give an agent a behavior specification and ask it to implement the viewer in each repository.

Benefits

  • Any runtime or custom server integration.
  • No dependency on a shared viewer release.

Costs

  • Fixes and browser checks repeat in every project.
  • Behavior and design can drift.

Shared authoring workflow

A skill carries conventions and setup instructions. Each repository still owns its viewer implementation.

Benefits

  • Consistent editing guidance for agents.
  • Flexible project-specific adaptation.

Costs

  • Instructions do not distribute tested executable behavior.
  • Local dependencies and fixes remain duplicated.

Shared viewer, local content

Pin one viewer through a flake input. Store documents and small navigation/style configuration in the consuming repository.

Benefits

  • Dependencies stay in the Nix store.
  • Shared fixes and deliberate, pinned upgrades.

Costs

  • Server extensions require a shared change or a fork.
  • Consumer environments need Nix.
